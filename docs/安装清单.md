## 怎么判断成没成

| 你看到的 | 含义 |
|---|---|
| 收到「模拟回复：XXX」 | 链路通了（回声模式） |
| 收到正常回答，且是你填的那个模型的风格 | **真接通了** |
| 收到很像她的回答，但**没有**「模拟回复」前缀 | **插件没接管**，是鲸鲸自己的模型在答 |
| 完全没回复 | 桥接没跑起来，看设置页那个圆点 |

**第三行是最容易误判的**——今天晚上就发生过一次。判断标准只有一条：你的插件接管时，回声模式下一定有「模拟回复：」。切到真思考后，看 DSH 设置页的日志有没有请求进来。

## 2026-11-15 22:50 真正的根因（第三个错）

前两次都没找对。这次是**实测出来的**，不是猜的。

DSH 找客户端插件的路径是 **`<包名>/client`**。用 Node 的解析器一测就清楚了：

```
dsh-phone/client            -> OK  ...lib/client.js
dsh-meme/client             -> OK  ...client.js
dsh-independent-input/client -> OK  ...client.js
whale-dsh-bridge/client     -> FAIL(MODULE_NOT_FOUND)   ← 就这里
```

我的 `package.json` **没有 `exports` 字段**，所以 `whale-dsh-bridge/client` 解析不到 —— **前端从来没被加载过**，一次都没有。

（host 半边一直是好的：`/plugins/dsh-whale-bridge/service` 一直 200。所以服务端正常、前端全无，这个组合本身就说明是"找不到文件"，不是"渲染错了"。）

**修复**：`package.json` 加

```json
"exports": {
  ".": "./plugin/apply.mjs",
  "./client": "./plugin/client.js",
  "./cordis.patch.yml": "./plugin/cordis.patch.yml",
  "./package.json": "./package.json",
  "./*": "./*"
}
```

修完再测同一个解析：**`whale-dsh-bridge/client -> OK \plugin\client.js`**。

同时把 `dsh.client.inject` 补成 `["@deepseek-ai/dsh-client-ui-slots", "@deepseek-ai/dsh-client-ui-sidebar"]`（左侧栏要用后者，`dsh-phone` 也是这么写的）。

现在去重启 DSH。

## 2026-11-16 00:58 真正的根因：注册 id 不等于包名

**`dsh-meme/client.js` 第 8 行自己写着答案：**

> 注册 id 必须等于 loader entry 名（dsh-meme），否则 ModuleLoader 报
> `loaded without registering dsh-meme`

我写的是 `id: 'dsh-whale-bridge'`，而**包名是 `whale-dsh-bridge`**（没有 `dsh-` 前缀）。

不一致 → 加载器认为这份注册"没有归属" → 于是反复注册 → 崩溃日志里那句
`duplicate factory registration for "dsh-whale-bridge"` 就是它。

（注意崩溃日志里点名的是 `dsh-whale-bridge`——那正是我写错的 id，不是包名。之前一直没往这上面想。）

**全机对照（都是 id = 包名）：**

| 插件 | 注册 id | 包名 | |
|---|---|---|---|
| dsh-meme | dsh-meme | dsh-meme | ✔ |
| dsh-independent-input | dsh-independent-input | dsh-independent-input | ✔ |
| dsh-phone | dsh-phone | dsh-phone | ✔ |
| **whale-dsh-bridge** | ~~dsh-whale-bridge~~ → **whale-dsh-bridge** | whale-dsh-bridge | 已修 |
